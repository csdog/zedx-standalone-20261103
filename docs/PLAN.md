# ZedX 实施计划

日期：2026-10-30

## 目标与已确定范围

维护 Zed 的个人 fork，名称为 ZedX。保留 Zed 的编辑基础和性能特点，先改造为 IDEA 式界面与工作方式。第一步用本地单文件 HTML 确认布局和交互，再进入 Rust 实现。

本项目已从 Zed `v1.26.2` 建立本地 fork，正在接入原生 UI。首轮不重写文本引擎，不开发自己的编译器语义分析，不扩展整套插件 API。后续需求在界面验证后按实际使用排序。

交付：

- [x] `prototype/index.html`：零外部依赖的工作台原型。
- [x] IDEA 式左右竖向工具栏、项目树、编辑器标签、底部工具窗口。
- [x] 项目 / 搜索 / Git / 结构切换；终端 / 运行 / 问题切换。
- [x] 文件预览、搜索浮层、明暗主题、面板尺寸拖动。
- [x] README、设计说明和分阶段实施计划。
- [x] 浏览器视觉与关键交互检查通过，记录验证结果。
- [x] 用户评审界面并授权开始原生代码实现。

验收：本地浏览器可直接打开；桌面布局无内容遮挡；工具栏、标签、搜索、面板尺寸和明暗主题可交互；窄屏可访问核心区域；没有外部请求、真实 shell 执行或真实 Git 操作。

## P1：建立可持续维护的 Zed fork

实施：

1. 选定 Zed 稳定 tag / commit，记录基线、许可证及第三方声明。
2. 在当前项目中保留原型和设计记录，再导入上游历史；保留既有文件，具体导入方式在执行前确认目录冲突情况。
3. 配置 `upstream` 为官方仓库；个人远程仓库待用户指定后再配置和推送。
4. 首先验证未修改的上游能在本机编译运行。
5. 将 fork 专用文档与补丁拆分为清晰提交；暂不做无关重构。

验收：基线可编译；能并行运行官方 Zed 与 ZedX；上游来源和自有补丁可追踪。

## P2：品牌与工作台布局

实施：

1. 核对应用名称、bundle identifier、图标、配置路径、缓存和更新渠道，建立 ZedX 独立身份。
2. 从 `crates/workspace` 的 `Workspace`、`Dock`、`Panel`、`StatusBar` 入手；复用现有面板注册与切换。
3. 参考社区 Activity Bar PR #58868 的设计和补丁，但先验证其与所选基线的适配情况，不假定可以直接合并。
4. 实现可配置的左右竖向工具栏、活动状态、提示、快捷键和隐藏 / 恢复入口。
5. 先保持现有 Dock 生命周期，再根据原型评审结果考虑同侧分区。
6. 为布局位置、尺寸和可见性建立持久化与恢复策略。

验收：项目、Git、搜索等窗口能够切换与恢复；编辑区尺寸正常；快捷键不冲突；重启恢复布局；不存在重复入口与不可达面板。

## P3：使用体验打磨

按实际使用反馈排序：

- 导航、最近文件、Search Everywhere 的体验一致性。
- 面板焦点返回、Esc 行为、工具提示与菜单。
- 文件树、编辑器标签、拆分与工具窗口的拖动行为。
- 运行 / 调试 / 终端入口的可发现性。
- 中文输入法、Retina 与多屏场景。
- 主题、字体、键位和工作区设置。

语言补全和精确导航继续使用现有 LSP。自定义数据库 / HTTP 等功能及开放 UI 扩展 API，另行评估，不与首轮布局改造混做。

验收：用实际开发项目完成打开文件、搜索、跳转、运行、调试、提交检查等日常流程。

## P4：性能与上游同步

- 使用相同 commit、构建模式、项目和语言服务，对比 Zed 基线与 ZedX。
- 统计完整进程树内存，单列语言服务器；记录冷启动、热启动、空闲和编辑时数据。
- 完成一次上游更新合并演练，记录冲突点与维护时间。
- 检查目标平台构建、发布包名称、应用数据隔离和更新入口。

验收：性能差异有实测数据和解释；核心布局补丁集中；可重复构建与同步；不依赖未经验证的内存承诺。
